# 技术决策记录

## 正式与测试各部署一整套 Piggy

**原因。** 软件仍在快速迭代，测试手机需要频繁验证新版，日常使用的手机需要稳定。同时，Go 网关按本环境的最新 `versionCode` 接受手机请求；只分开 APK 下载地址，仍会让旧版手机被共享网关拦住。

**选择与后果。** 两个 Android 包名允许同机安装。每个包连接固定的 HTTPS 入口，后面各有 Go 网关、Pi、管理凭据、SQLite、附件目录和更新清单。这样可以在测试环境独立改协议、改模型、试数据库迁移，最后再决定何时正式发布。两套部署共用一台 CVM；当前也共用 OpenAI 密钥，所以主机故障和上游配额仍是共同边界。实现见 [Android 构建配置](../android/app/build.gradle)和[服务构建脚本](../server/admin/build-release.sh)。

## 手机发起对话，服务端持有 Agent

**原因。** 模型、工具和用量需要集中管理；手机操作要简单。**选择与后果。** Android 通过固定地址免登录发消息，Go 网关转给 Pi，OpenAI 密钥由服务端持有。网页版须登录，可以看历史、Agent 能力和调整模型设置。对话维持单向写入，网页不续聊，因此手机无需同步来自网页的新消息。网页保存的模型配置作用于本环境的下一次请求。实现见 [Go 网关](../server/admin/main.go)和 [Pi 服务](../server/server.ts)。

## 聊天原文与模型上下文分别保存

**原因。** 网页要保留用户实际看到的问答；压缩模型输入时，这份历史仍然有用。**选择与后果。** SQLite 的 `turns` 保存原文与状态，`active_context` 按会话顺序保存工作上下文；成功结束一轮时一并提交。手机展示最近 40 轮属于本地显示策略。模型输入读取工作上下文，按实际请求计数，正式版上限为 300,000 个输入 token，测试版为 30,000，方便用较短对话验证压缩。早期开发阶段允许旧会话恢复时缺少工作上下文，这个容忍范围不构成今后正式数据迁移的承诺。实现见 [Journal](../server/journal.ts)和 [Pi 服务](../server/server.ts)。

## 在每次生成前压缩超过 80% 的工作上下文

服务端先用模型的计数接口检查本次完整输入，包括系统提示、技能、工具、附件和新问题。超过本环境窗口的 80% 时（测试版为 24,000 tokens），用当前模型单独总结较早的可见对话，尽量原样保留最近三轮。人格、技能与工具在正式请求中重新组装。即便上次用量只有 79%，本次预检也能先发现超限。圆环在单独的队列里向服务端读取用量，界面保留最近一次成功同步的数值，忽略过期的刷新结果。发送时仍校验实际请求，遇到计数网络超时或上游临时服务错误会自动重试一次。实际回复可能使数字暂时上升，下次发送时再处理。

模型实际接收的聊天输入须落在本环境的上限以内。摘要失败时，预算内仍可用原历史回复，预算外保留原上下文并提示重试。新消息和附件本身接近上限时，优先给它们留足空间，这一轮能带的摘要可能很短甚至为空。如果连移除全部历史都放不下，提示缩短消息或减少附件。回复成功后才在同一事务中替换旧上下文、保存完整摘要和本轮问答，网页原文及七天附件引用继续保留。实现见[上下文压缩](../server/compaction.ts)。

## 长期记忆由用户明确发起

用户主动要求保存时，`save_memory` 接收证据摘录。服务端先让模型根据本次证据提取带原文片段的事实，复用当前会话目录中的人物和主题名称。匹配旧成员时只能选择键，新值来自先前的证据提取。已有值的替换、删除和需要进一步核对的规范表述会独立审查。第一人称使用王子怡，其他人物、否定、时间、程度和条件各自保留。

SQLite 事务负责应用修改。主题 ID 和成员 ID 稳定，`memory_members.turn_id` 指向每项的最近确认，`memory_changes` 记录历次证据。同一轮同一摘录重复提交可复用结果。工作上下文压缩与这些表独立。用户要求列全时，`list_memory_topics` 分页列目录，`read_memory_topic` 按返回的编号读成员，再用成员的来源轮次回查聊天。实现见[主题存储](../server/memory-topics.ts)和[记忆整理](../server/memory-planner.ts)。

## 附件保留七天，文档在手机上排版

**原因。** 手机要能查看双方的附件，管理页要能下载；永久存原件会持续占用服务器磁盘。服务端转换 Office 文档还会增加传输往返和 CVM 负载。**选择与后果。** 上传件和模型生成件都以文件形式限期保存，数据库记录引用、名称和期限。到期清理原件，历史消息继续保留文件信息。Android 在 APK 中内置 LibreOfficeKit，已在手机上的文档首次预览也能离线打开；远端附件需要先下载。实现见[文件留存](../server/retention.ts)和[手机 Office 阅读器](../android/app/src/main/java/dev/pichat/OfficeReader.kt)。

上传件只在所属用户消息上引用。计数、生成和工具续轮使用相同的文件引用。压缩移除原消息后，可按聊天关键词或文件名查找历史轮次，再通过 `read_chat_context` 重读该轮仍有效的原件。

## Android 本地草稿

输入时保存文字。点击发送会一并保存本条消息和重试编号，随即腾出输入框供用户写下一条。等待期间可以编辑下一条的文字、选择或移除本地附件。待发送消息与下一条草稿分别保存各自的附件列表，点击发送后才上传。回复成功后保留下一条草稿；失败时如果已经写了下一条，可单独处理上一条，两份内容都可跨进程重启恢复。

## 保留签名整包，更新时复用文档引擎

**原因。** 手机需要启动时强更以匹配本环境的接口，而一次普通界面改动无需重传几十 MB 的相同引擎。**选择与后果。** 发布器标记签名 APK 中的引擎区间。手机校验本地引擎匹配后，只下载该区间前后的两段，在本地还原安装包，检查大小、哈希、包名、版本和签名，再交给系统安装。引擎变化或增量失败时自动下载整包。进度条按本次网络下载量计算；手机需留出完整 APK 的临时空间。实现见[发布器](../server/admin/updates.go)和[安卓更新器](../android/app/src/main/java/dev/pichat/AppUpdater.kt)。

### 测试版长期记忆的向量索引

每个会话单独为当前主题正文建立 OpenAI 向量索引。重新确认相同内容只更新出处。正文发生变化时立即撤销旧文件的本地映射，持久队列为新正文建索引并清理旧版主题文件。查询结果按本会话和当前文件编号核对。相关性搜索每次最多请求 20 个候选，完整枚举走 SQLite 目录和成员分页。

迁移仅整理旧 `memories` 表中仍有效的记忆，按来源轮次处理。旧记录及其原始向量映射保留供核对，主题向量使用独立的会话向量库。导入记录和成员变更在同一事务中提交。服务中断后可继续，迁移未完成的会话仍可聊天和读取已就绪的主题，新记忆写入会提示稍后重试。
